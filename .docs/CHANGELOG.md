## 2026-10-28 (Full functional audit — Phase 0–6 validation & hardening)

- **Scope:** automated end-to-end audit of every implemented Phase 0–6 workflow (auth, projects, story/scene planning, provider layer, images, audio/licensing, rendering, frontend wiring). All baseline checks re-executed and green; 21 regression/coverage tests added (418 total, 2685 assertions, 0 failures); real-FFmpeg integration tests re-run against the actual binaries (2/2, not skipped); `render:smoke` re-run on the real pipeline. No new features; no provider/pricing/licensing changes; Phase 7 not started.
- **Bug fix — regeneration destroyed the new artifact file (data loss):** `VoiceAudioPersister`/`ImageAssetPersister` deleted the previous asset's file even when the provider had just rewritten the SAME content-addressed path (identical text/voice or scene inputs), leaving the freshly created `assets` row pointing at a deleted file (render pre-flight would later fail "file is missing from storage"). Fix: the file delete is skipped when the old row's disk+path equals the incoming result path; the row replace is unchanged. Regression tests assert file existence after identical-content regeneration (audio + scene image).
- **Bug fix — TTS `instructions` sent to models that do not support them:** inverted condition in `OpenAITtsProvider` attached `instructions` only to `tts-1`/`tts-1-hd` (documented as NOT supporting them) and stripped them from `gpt-4o-mini-tts` (which supports them) — opposite of `config/ai.php` `models_without_instructions` intent. Fixed + two-directional HTTP-fake regression tests.
- **Bug fix — stuck intermediate states on failure paths:** dialogue lines stuck in `generating` (silent-mode defensive cancel, emptied text mid-queue, non-provider job failures) and scenes stuck in `image_generating` (non-provider failures) are now always reset to `failed`; previously only `ProviderException` reset them, which would block the render pre-flight forever. Latent `error_class` truncation (string(120) column) applied to all six job failure paths + `ProviderCallRecorder` (MySQL strict mode would have made failure recording itself fail; `RenderVideoJob` already truncated).
- **Bug fix — success/warning flash feedback never rendered:** 37 controller flashes used `success`/`warning` keys but the Inertia middleware shared only `status`, so operation feedback (project created, upload quarantined, licence verified, …) was invisible. Middleware now shares `flashSuccess`/`flashWarning`; `AppLayout` renders the banners (regression-tested via Inertia props).
- **Bug fix — invisible validation errors in the UI:** narration-voice form read a nonexistent `narration` error key (backend validates `voice`/`instructions`/`speed`); render page showed no launch errors (`render` key); storyboard completion `status` errors and reorder `scene_ids` errors were unrendered; upload/licence forms rendered only 2 of ~8 keys. All surfaces now display their backend error keys.
- **Bug fix — polling blind spots:** storyboard polling stopped while character-reference jobs were still running (only plan/image jobs were watched — the page never saw the reference phase of "Generate scene images"); backend now passes `referenceJobs`/`referenceJobActive`, the storyboard renders them and keeps polling. Story editor now also polls `planJobActive` (re-entering mid-plan no longer leaves the button disabled until manual refresh).
- **Bug fix — voice jobs never healed when stuck:** `audio.generate` now cancels stale (worker-crashed) voice rows first like story/plan/render/image flows already did; previously a crashed voice job kept the UI polling forever and blocked the subject.
- **Bug fix — required `authUser` prop on every page:** nine pages declared `authUser: required` but no controller passes it (Vue missing-prop warning on every visit); now `default: null` with the existing `AppLayout` fallback to the shared `auth.user`.
- **Hygiene:** removed a committed debug artifact from `CharacterTest` (conditional `migrate:fresh --force` inside a feature test + a hardcoded temp-path debug dump); `render:smoke` now disposes of its `smoke/images`+`smoke/audio` fixture files (previously orphaned on the private disk; existing orphans deleted).
- **Coverage added (no product-code change):** login rate limiter (5-attempt lockout) + authenticated-user `/login` redirect; `projects.create` page render; narration-voice save/validation/authorization; audio-asset delete (owner file+row+licence removal, music/SFX-only guard, stranger 403); storyboard reference-job props. `Story/Edit.vue` reordered to the repo's `script` → `template` SFC convention (D-023).
- **Verification:** `php artisan test` → **418 passed / 2685 assertions / 0 failures** (MySQL `cartoon_studio_testing`); `RenderIntegrationTest` 2/2 with the real FFmpeg 9.0.2 binaries; `render:smoke` OK (h264/1080×1920/30 fps/yuv420p + AAC, 30.0 s, thumbnail+SRT) and leaves no fixture files; `npm run build` ✓; `vendor/bin/pint --test` ✓; `composer check-platform-reqs` ✓; `php artisan ffmpeg:check` ✓; `git diff --check` ✓; zero TypeScript files; SFC order scan clean; suite still pinned credential-free (`Http::preventStrayRequests()` + empty provider env). **Not verified (needs a real OpenAI credential):** live text/image/TTS calls; browser-level UI interaction (no browser-test stack in the repo). **Next task:** Phase 7 — Hardening.
