## 2026-10-28 (Phase 4 — Cartoon images)

- **Provider decision (D-007 image portion Confirmed):** OpenAI Image API verified against official docs on 2026-10-28 — `POST /v1/images/generations` (JSON), `POST /v1/images/edits` (multipart with `image[]` reference inputs), `data[0].b64_json` + `usage` response, sizes 1024x1024/1024x1536/1536x1024, quality low→max, `gpt-image-2.5-flare` pricing $5/$8/$30 per MTok, Build tier 250K TPM / 20 IPM. Gemini's docs were reachable but only fragments were obtained — recorded as the unverified alternative. Evidence: [reference/API_RESEARCH.md](reference/API_RESEARCH.md).
- **Real image adapter:** `App\AI\Providers\OpenAI\OpenAIImageProvider` (`ConfigurableProvider` + `ImageProvider`) — character references via generations; scene images via edits **with the stored character reference images attached** (D-011, best-effort consistency). Response `b64_json` decoded + `getimagesizefromstring`-validated before persistence; artifacts written to the private disk under `openai/image/{kind}/{fingerprint}.{ext}`; no URLs stored; secrets redacted through the existing HTTP-client/exception pipeline. Sizes/quality/format configurable (`OPENAI_IMAGE_*` envs, provider-setting `config` overrides).
- **Prompt builders:** `App\AI\Prompts\ImagePromptBuilder` — character reference sheets and scene prompts composed from product data only (image prompt, background, characters present + their style anchors, project `visual_style`, vertical 9:16 composition guidance).
- **Jobs + orchestration:** `GenerateCharacterReferenceJob` (per character) and `GenerateSceneImageJob` (per scene) — `$tries = 1` with gateway-level retries, per-subject `WithoutOverlapping`, duplicate-dispatch short-circuits (`skipped`), scene status transitions `image_pending → image_generating → ready|failed`, missing-reference prerequisite fails the job with an actionable message while the scene stays retryable. `SceneImageDispatcher` enforces ordering (scene jobs queue only once all required characters have references; fan-out when the last reference lands). `GenerationJobGuard` gained subject-scoped active/stale checks (`payload->character_id` / `payload->scene_id`).
- **Persistence + cost:** `ImageAssetPersister` (private-disk artifacts, `assets` rows with provider/model/width/height/checksum meta, character/scene links, regeneration replaces file + row transactionally); `OpenAICostEstimator` extended for image estimates (verified flare rates + documented estimate constants); daily budget ceiling enforced pre-call unchanged.
- **HTTP + UI:** new routes `characters.generate-reference`, `scenes.generate-image`, `storyboard.generate-images` (batch fan-out with queued/waiting summary) and `assets.show` (policy-checked private-asset streaming via new `AssetPolicy`/`AssetController`). Storyboard page: "Generate scene images" batch action, per-scene thumbnail/status/error/regenerate, image-job activity list, 3 s polling; Characters page: reference thumbnails, generate/regenerate, job list, polling.
- **Tests:** +31 (`Phase4/ImageGenerationTest` ×13 — pipeline, dependency ordering, regenerate isolation, dedupe, failure isolation, missing-credential actionable failure, asset authorization/404/403, duplicate-concurrent block; `Provider/OpenAI/OpenAIImageProviderTest` ×8 — request shape, edits-with-references, 401/429/500 mapping + key redaction, empty/invalid b64; `Unit/Prompts/ImagePromptBuilderTest` ×5; estimator image cases). Verification: `php artisan test` → **271 passed / 1696 assertions**; `npm run build` ✓; Pint ✓ (204 files); `composer check-platform-reqs` ✓; route list ✓; no schema changes; zero paid calls in the suite. **Manual real-key test pending user credential.** **Next task:** Phase 5 — Audio.

- **Navigation (AppLayout):** fixed a state bug where the header always rendered guest links — pages declared an `authUser` prop the backend never sent; the layout now falls back to the shared `auth.user`. Added brand mark, active-page highlight, avatar initials, a styled logout (still the CSRF-protected `POST /logout` with session invalidation + token regeneration) and a responsive mobile nav row. Guest vs. authenticated states are both handled. Covered by new `LogoutTest`.
- **Account settings:** new `password.edit`/`password.update` routes (auth group, CSRF-protected), `PasswordController` + `UpdatePasswordRequest` Form Request (`current_password:web`, `Password::min(8)`, `confirmed`), and `Settings/Password.vue` with three independent show/hide eye toggles (`type="button"`, `aria-label`/`aria-pressed`, values preserved on toggle). Passwords are hashed with `Hash::make`, the session `password_hash_web` is kept in sync, and no password is logged or echoed. Covered by `PasswordUpdateTest`.

Story Editor keeps its styling; story generation, saving and scene planning untouched.
- **Dashboard:** creator-workspace header with derived project/scene counts, improved project cards (updated dates from the controller, consistent actions) and a proper empty state. Data remains the real controller/Inertia payload (+`updated_at`); ownership/authorization untouched.
- **Verification:** `php artisan test` → **240 passed / 1503 assertions** (Phase-3 baseline 228/1433; includes the previous sprint's in-tree regression tests and 9 new logout/password tests); `npm run build` ✓ (JS only, zero `.ts`); `vendor/bin/pint.bat --test` ✓ (192 files); `git diff --check` ✓; `php artisan route:list` ✓. ## 2026-10-27 (Phase 2)

- **Phase 2 — Provider layer implemented.** Four capability contracts (`TextProvider`, `ImageProvider`, `TtsProvider`, `MusicProvider` in `App\AI\Contracts`) with provider-agnostic input/result VOs (`StoryBrief`, `ScenePlanConstraints`, `CharacterBrief`, `SceneBrief`; `StoryDraft`, `ScenePlan`, `ImageResult`, `AudioResult`, `ProviderUsage`); typed exception taxonomy (`ProviderConfigurationException/Auth/RateLimit/Timeout/Request` + `ProviderHttpError` status mapping with `Retry-After` parsing). `ProviderRegistry` (config-driven; `test_only` entries hidden outside testing) + `ProviderManager` (project override → active default setting → env; actionable errors; **no silent fallback**). `CredentialStore`: env-first with encrypted `provider_settings.credentials` fallback, switchable via `PROVIDER_CREDENTIAL_STORE=env|database` (D-021; empty string = no stored credential). `ProviderGateway`: pre-call `DAILY_PROVIDER_BUDGET_USD` ceiling check, bounded exponential backoff with jitter + `Retry-After` awareness, **per-attempt `provider_calls` ledger rows** (capability, provider, model, status, http_status, estimate/actual, tokens, duration, `request_fingerprint`, sanitized error). `ProviderHttpClient` + `SecretRedactor`: provider HTTP logging with authorization headers/keys/secret params redacted — real request headers untouched on the wire.
- **Settings UI + rules:** `/settings/providers` Inertia page (JS-only) for system provider settings with write-only credential field ("API key saved (hidden)" indicator), per-capability default exclusivity (application-enforced in a transaction), activate/deactivate/delete with dangling project-override cleanup; `ProviderSettingsRequest` + `ProviderIsKnown`/`ProviderConfig` rules reject unknown providers and unknown config keys. Authorization: any authenticated user in the MVP (D-019); `ProviderSettings` gains `#[Hidden(['credentials'])]` so serialization can never leak it. Per-project override resolution shipped and tested; override UI deferred to Phase 3 (D-022).
- **Fakes + tests:** deterministic fake providers for all four contracts (tiny valid PNG/WAV fixtures written to the private test disk) with injectable failures (auth/rate-limit/timeout/malformed/request), registered in testing only (D-020: registry has no real vendors until D-007 verifies them). `Http::preventStrayRequests()` enforced suite-wide. New factories: `ProviderSettingsFactory`, `ProviderCallFactory`, `GenerationJobFactory`.
- **Verification:** `php artisan test` → **172 passed / 1170 assertions** (baseline 70/237 — all Phase 0/1 tests still green; zero network calls; no schema changes, `migrate:status` clean); `npm run build` ✓ (JS only); Pint ✓. Docs updated: [phases/PHASE_02_PROVIDER_LAYER.md](phases/PHASE_02_PROVIDER_LAYER.md), [PROVIDER_INTEGRATION.md](PROVIDER_INTEGRATION.md) (final contract signatures), [DECISIONS.md](DECISIONS.md) (D-019–D-023), [DATABASE_DESIGN.md](DATABASE_DESIGN.md) (credential sentinel note), [PROGRESS.md](PROGRESS.md).
